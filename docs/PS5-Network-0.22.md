# PS5 Network 0.22

Один ELF для PS5 на прошивке **12.20**. Веб-панель на порту **8095** управляет sing-box 1.14.4, перехватом по процессу и проверками соединения. Панель запускает встроенный sing-box через локальный ELF-загрузчик `127.0.0.1:9021`, которым также пользуется Payload Manager.

## Переход на новую сборку

1. Нажми **Завершить работу** в панели предыдущей версии. Если отдельно запущен sing-box, останови его, чтобы освободить порт 17890. Если эти ELF стоят на автозапуске, выключи для них автозапуск.
2. Оставь системный прокси выключенным и запусти `elf/ps5-network-v22.elf` через веб-интерфейс Payload Manager.
3. С компьютера открой `http://IP-твоей-PS5:8095` и введи восьмизначный код из уведомления. На самой PS5 открой плитку **Мультимедиа → PS5 Network**: локальная панель `http://127.0.0.1:8095/` войдёт автоматически, без кода и пароля. Существующую плитку переустанавливать не нужно.

Сборка подхватывает существующий `/data/ps5-local-proxy/config.json` и пишет общий журнал в `/data/ps5-local-proxy/tcp-relay.log`. Профиль должен содержать один `mixed` на `127.0.0.1:17890` без аутентификации и TLS на входе, с `set_system_proxy: false` или без этого параметра. Для самотеста в профиле нужна прямая маршрутизация `127.0.0.0/8` к `direct`. После редактирования профиля через PS5 Web File Manager нажми **Перезапустить sing-box**.

Панель задаёт имя `ps5-net-panel.elf`, а встроенный прокси — `ps5-singbox.elf`. Журнал содержит PID и имя, которое вернуло ядро. Готовый прокси отмечен статусом **sing-box · Запущен** и строкой `HTTP/SOCKS5 proxy ready at 127.0.0.1:17890`.

## Перехват

- Запусти Orbit обычным способом и дождись появления каталога. В панели нажми **Orbit и WebView через VPN**. Панель определяет процесс по порту 34177, сверяет три фрагмента его кода с `/data/orbit-store/orbit_store.elf`, а при несовпадении — со встроенным `app0/orbit/orbit_store.elf` из `/mnt/sandbox/PPSA99177_<номер>/` и проверяет адрес импорта `connect()` перед установкой перехвата в память.
- После `Orbit VPN active` начни новую загрузку из Orbit. `Orbit relay #` в журнале означает, что новый внешний IPv4 TCP-запрос попал в ретранслятор. Если ни один ELF не подошёл, при успешном самотесте WebView панель продолжит наблюдать за его сетевым процессом и покажет «Работает только WebView». Это не подтверждает перехват Orbit.
- **Остановить** снимает перехваты. Для нового сеанса нажми **Orbit и WebView через VPN**.
- Чтобы выбрать Payload Manager или другое приложение, раскрой **Другой процесс**, выбери процесс и нажми **Перехватить процесс**.
- Режим **Другой процесс** использует трассировку новых TCP-соединений к публичным IPv4-адресам выбранного процесса. **Завершить работу** отключает панель и встроенный sing-box.

## WebView и Orbit

1. Нажми **Orbit и WebView через VPN**. Самотест проверяет вызов `getpid` одиночным шагом отладчика, подменяет указатель `connect` в дочернем процессе и проверяет три TCP-обмена через sing-box. Клиент обращается к `127.0.0.2`, а тестовый сервер слушает только на `127.0.0.1`. После `PASS: WebView preflight` панель ищет `SceNKNetworkProcess` или `SceNKNetworkProc`. При ошибке `WebView syscall …` журнал содержит сигнал и адрес остановки. Панель проверяет и подключает процесс Orbit отдельно.
2. Открой Vikingfile или AkiraBox из Orbit. Дождись `WebView connect route installed` или `WebView syscall capture active` для сетевого процесса и обнови страницу. `WebView TCP #…` и `SOCKS5 OK #…` с тем же номером подтверждают открытие соединения через sing-box. Пройди проверку вручную и дождись, пока Orbit подхватит ссылку. [Руководство Orbit](https://github.com/saawant12/orbit-store-ps5/blob/main/guides/downloads.md)
3. **Проверить WebView на PS5** открывает в системном браузере страницу с внешним IPv4. Сравни IP с журналом проверки HTTPS. Нативное окно провайдера проверяй из Orbit, поскольку оно может открывать отдельный сетевой процесс.

Панель ждёт загрузки WebKit и curl, затем ищет импорты BSD `connect` и `_connect` по записям релокации. Она сверяет адрес каждого импорта с картой памяти процесса и ждёт, пока загрузчик привяжет импорты обеих библиотек к сетевым функциям. Обработчик использует сетевые функции и `errno` штатной библиотеки `libkernel_web`. После установки обработчика панель отсоединяет отладчик. При остановке панель восстанавливает указатели и проверяет результат. Страницы освобождаются при выходе процесса.

Если чтение инструкции `getpid` через отладчик возвращает `EFAULT`, панель пробует чтение через PS5 Payload SDK. Строка `getpid text source=SDK` показывает результат чтения. Успешную установку подтверждает `WebView connect route installed` для PID `SceNKNetworkProcess` и последующий `WebView TCP #…`.

Панель повторяет проверку импорта, если сетевой процесс ещё запускается. Запасная трассировка доступна после готовности WebKit и curl, если панель полностью откатила неудачную установку. Она направляет новые TCP-соединения к публичным IPv4 через тот же ретранслятор sing-box. Этот режим останавливает процесс на каждом входе в системный вызов и может замедлить браузер. Отчёт содержит число входов в системные вызовы, попыток `connect` и перенаправлений.

## Проверки

- **Проверить HTTPS** показывает внешний IP при обращении к `api.ipify.org` через HTTP и SOCKS5. IP и ошибки видны в журнале.
- **Тест загрузки** читает 4 МиБ через прокси, а в журнал пишет число полученных байтов и скорость. Если на консоли уже есть `/data/ps5-local-proxy/download-url.txt` c HTTPS-ссылкой, проверка запрашивает первый МиБ по этой ссылке.
- **Самотест** проверяет три локальных TCP-соединения с перенаправлением через sing-box. Это проверка перехвата, даже если внешняя сеть недоступна.

Чтобы измерить скорость туннеля, запусти **Тест загрузки** между скачиваниями. Сравни его с длинным соединением Orbit в `diagnostics.txt`. В строке `TCP relay=` поле `socks_ms` показывает время до подтверждения SOCKS5, `first_rx_ms` — время от подтверждения до первых данных от sing-box, `rx_span_ms` — время от первых полученных до последних переданных приложению байтов. `app_wait_ms` показывает, сколько ретранслятор провёл в ожидании, пока данные были в очереди на отправку приложению. Для этих замеров достаточно строк журнала.

## Диагностика

1. Нажми **Собрать диагностику**. Панель трижды проверит выделение памяти и TCP-обмен WebView. Затем она запустит три тестовых ELF через локальный загрузчик. `plain-probe` проверяет вход в обычный ELF. `original-entry-probe` добавляет перенаправление `connect` с исходной точкой входа. `gated-probe` проверяет подтверждение старта и затем `connect`.
2. Когда панель покажет **Ожидает сетевой процесс** или **Перехват установлен**, открой окно провайдера из Orbit. Кнопка **Проверить WebView на PS5** запускает системный браузер для дополнительной проверки. Диагностический режим подключает только перехват WebView. Если все три локальных проверки WebView завершились ошибкой, переходи к скачиванию отчёта.
3. Нажми **Скачать диагностику**. Тот же отчёт хранится в `/data/ps5-local-proxy/diagnostics.txt`. Остановить наблюдение можно кнопкой **Остановить**.

Отчёт содержит прошивку, результаты `ptrace`, адреса и размеры выделенной памяти, имена найденных процессов и модулей, этапы запуска ELF и счётчики ретранслятора. Из вывода загрузчика сохраняются распознанные статусы и сообщения тестовых программ. Файл начинается заново при запуске панели.

## Сборка

На Linux x86-64 запусти `./build.sh`. Скрипт проверяет SHA-256 PS5 Payload SDK 0.45 и Go 1.27.1, применяет патч Go для PS5 и собирает libmicrohttpd из приложенного архива. Можно указать готовые инструменты в `PS5_PAYLOAD_SDK` и `PS5_PATCHED_GO_ROOT`. LLVM, Python 3, make и GNU binutils должны быть доступны в PATH. Результат находится в `elf/`. Контрольная сумма ELF включена в архив.

Загрузчик Go и адаптация Go основаны на [ps5-tailscale](https://github.com/holdmysocks/ps5-tailscale/tree/e1618c10ac68108645a6bbb5fbefabc345398182). Исходники и лицензии sing-box, PS5 Payload SDK, libmicrohttpd и зависимостей приложены в `upstream/`, `core/vendor/` и `ui/`.

В 0.22 встроено то же ядро, что и в исходной 0.21. На PS5 12.20 проверены вход в локальную панель без PIN, отказ выдавать локальный сеанс клиенту из LAN, подключение сервиса Orbit из кэша и из TV-приложения, а также установка и снятие перехватов Orbit и WebView. В журнале видно, какой из файлов Orbit совпал с работающим процессом. [Изменения и детали проверки](CHANGELOG.md).
